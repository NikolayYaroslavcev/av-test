# Техническое задание: Интерактивный компонент «Плеер решения билета ПДД»

## 1. Задача

Сверстать адаптивный интерактивный компонент на **Vue 3 + Tailwind CSS** (либо Vanilla CSS, если Tailwind не подключён в проекте), реализующий прохождение билета ПДД из 20 вопросов с проверкой ответов, избранным и Paywall-заглушкой.

**Скоуп: 8 часов.** Референсы и текстовое описание — от заказчика (см. п.2). Формат данных — как в GitHub-репозитории https://github.com/etspring/pdd_russia.

## 2. Модель данных

Пример реального объекта вопроса (`Билет_1.json`, массив из 20 таких объектов):

```ts
interface Answer {
  answer_text: string;
  is_correct: boolean;
}

interface Question {
  title: string;              // "Вопрос 1"
  ticket_number: string;      // "Билет 1"
  ticket_category: string;    // "A,B"
  image: string;               // "./images/no_image.jpg"
  question: string;            // текст вопроса
  answers: Answer[];           // 3-4 варианта, ровно один is_correct: true
  correct_answer: string;      // "Правильный ответ: 2" — человекочитаемая строка, НЕ парсить для логики
  answer_tip: string;          // пояснение к правильному ответу (показывать после ответа)
  topic: string[];             // ["Общие положения"]
  id: string;                  // уникальный id вопроса
}

type Ticket = Question[]; // массив из 20 вопросов
```

**Важно:** для логики "верно/неверно" использовать поле `is_correct` внутри `answers[]`, а не парсить строку `correct_answer` — она чисто для отображения (можно вывести в `answer_tip`-блок после ответа).

## 3. Состояние компонента (стейт-модель)

```ts
type AnswerStatus = 'unanswered' | 'correct' | 'incorrect';

interface QuestionState {
  status: AnswerStatus;
  selectedAnswerIndex: number | null;
  isFavorite: boolean;
}

interface PlayerState {
  questions: Question[];           // данные из JSON
  currentIndex: number;            // 0-19
  questionStates: QuestionState[]; // параллельный массив состояний, по одному на вопрос
  isPaywallOpen: boolean;
}
```

Правила:
- После выбора ответа — `status` меняется на `correct`/`incorrect`, `selectedAnswerIndex` фиксируется, повторный выбор для этого вопроса **блокируется**.
- Переключение между вопросами (клик по номеру в навигации) не сбрасывает состояние — если вопрос уже отвечен, при возврате к нему видно зафиксированный результат.
- `isFavorite` переключается независимо от `status`, доступно в любой момент.


## 5. Пошаговый план реализации

### Шаг 1 — Настройка проекта и типов (~1ч)
- Создать Vue 3 проект (Vite): `npm create vite@latest -- --template vue-ts`
- Подключить Tailwind (`npx tailwindcss init -p`, настроить `content` в конфиге)
- Создать `types/ticket.ts` с интерфейсами из п.2-3
- Положить `ticket-1.json` в `src/data/`, импортировать как мок
- **Готово, когда:** проект собирается (`npm run dev`), данные типизированы и импортируются без ошибок TS

### Шаг 2 — Layout-каркас (~0.5ч)
- Собрать `TicketPlayer.vue` со слотами/зонами под: навигацию, медиа-блок, контент вопроса
- Только структура на Tailwind grid/flex, без данных и интерактивности
- Проверить на глаз пропорции блоков при ширине 375px и 1920px (просто ресайз окна)
- **Готово, когда:** видна структура плеера на обоих крайних размерах экрана

### Шаг 3 — Верхняя навигация по вопросам (~1–1.5ч)
- `QuestionNav.vue`: рендер 20 кликабельных элементов (номер вопроса)
- Состояния кнопки: активный (текущий вопрос) / решён верно (зелёный) / решён неверно (красный) / не отвечен (нейтральный)
- На мобильном — горизонтальный скролл с `scroll-snap`, на десктопе — можно в несколько рядов или вписать в ширину
- Клик по номеру → меняет `currentIndex` в родителе (`emit`)
- **Готово, когда:** клик переключает текущий вопрос, цвет элемента навигации соответствует статусу из `questionStates`

### Шаг 4 — Медиа-контейнер (~0.5–1ч)
- `MediaBlock.vue`: изображение вопроса (`aspect-ratio` фиксированный, `object-fit: cover`)
- Кнопка «3D-Видеоразбор» с иконкой замочка (можно взять из любого open-source icon set, напр. Heroicons — уже завязан на Tailwind)
- Клик по кнопке → `emit('open-paywall')`, логика открытия — в родителе
- **Готово, когда:** изображение не искажается при любой ширине контейнера, кнопка кликабельна

### Шаг 5 — Контент вопроса и варианты ответов (~1ч)
- `QuestionContent.vue` + `AnswerButton.vue`: текст вопроса, список ответов из `answers[]`
- Кнопки крупные, `min-height: 44px` (touch-friendly), достаточные отступы между ними
- На этом шаге — чистая вёрстка, без логики выбора (просто список кликабельных карточек)
- **Готово, когда:** варианты ответов рендерятся из данных, визуально не различаются по состоянию (это следующий шаг)

### Шаг 6 — Интерактивность: выбор ответа и избранное (~1.5–2ч)
- Клик по `AnswerButton` → обновление `questionStates[currentIndex]`: `status` = `correct`/`incorrect` (сверка с `is_correct`), `selectedAnswerIndex` фиксируется
- Визуально: выбранная кнопка подсвечивается зелёным (если верно) или красным (если неверно); если неверно — можно дополнительно подсветить зелёным правильный вариант
- Повторный клик по любому варианту после ответа — **не должен** менять состояние (disabled)
- `FavoriteButton.vue`: toggle локального состояния `isFavorite`, независимо от статуса ответа
- Обновление статуса в `QuestionNav` при ответе (реактивно, через общий стейт)
- **Готово, когда:** ответ фиксируется один раз, статус верно синхронизируется между контентом и навигацией, избранное переключается свободно

### Шаг 7 — Paywall-модалка (~1–1.5ч)
- `PaywallModal.vue`: оверлей + модальное окно, заглушка с текстом предложения Premium за 1₽, CTA-кнопка (без реальной оплаты — просто UI)
- Закрытие: клик по крестику, клик вне модалки (по оверлею), клавиша `Esc`
- Простая transition-анимация появления/исчезновения (`Transition` компонент Vue)
- **Готово, когда:** модалка открывается по клику на «3D-Видеоразбор», закрывается всеми тремя способами, не ломает скролл фона (при открытой модалке `body` не скроллится)

### Шаг 8 — Адаптив и финальная проверка (~1.5–2ч)
- Прогнать весь компонент на 375px (iPhone) и 1920px (десктоп), плюс пара промежуточных ширин (768px, 1024px) для подстраховки
- Поправить отступы, размеры шрифтов, расположение навигации под каждый диапазон
- Проверить: touch-таргеты ≥44px на мобиле, клик по модалке не глючит на тач-устройствах
- **Важно про доступность:** зелёный/красный не должны быть единственным индикатором статуса — добавить иконку (✓/✗) или текстовую подпись рядом с цветом (для дальтоников и скринридеров)
- **Готово, когда:** компонент выглядит и работает корректно на всех проверенных ширинах, нет горизонтального скролла страницы, нет наложения элементов
